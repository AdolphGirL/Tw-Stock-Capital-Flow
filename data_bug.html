Bug Report

上櫃資料「假新鮮」— 抓取失敗被靜默偽裝成已更新

個股掃描器顯示的上櫃成交金額與實際不符，追查後定位為 SyncManager 的日期回報邏輯遮蔽了單一市場抓取失敗的事實。

Confirmed Bug 上櫃 TPEX 已修正 2026-08-27

01問題回報

以 4991 環宇-KY（115/08/27）為例，App「板塊個股排行」顯示的成交金額與漲跌幅明顯異常：

欄位App 顯示（錯誤）官方正確值
成交金額24.04 億42.89 億（4,288,968,520 元）
漲跌幅+10%+9.91%（538.00 − 48.50 為前收 489.50）

使用者已嘗試點擊「立即重新整理」手動刷新，畫面數字仍未改變。

02驗證：官方 API 本身沒有問題

直接以 curl 呼叫 App 目前使用的端點，確認 TPEX 官方資料在當下是正確、即時的：

GET https://www.tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes

// 4991 環宇-KY，Date: "1150827"（今日）
{
  "Date": "1150827",
  "SecuritiesCompanyCode": "4991",
  "CompanyName": "環宇-KY",
  "Close": "538.00",
  "Change": "+48.50",
  "TransactionAmount": "4288968520"  // = 42.89 億，與正確值完全吻合
}
結論：API 資料正確、stock_service.dart 的欄位對應（TransactionAmount 等）也正確。問題不在資料源頭，也不在解析邏輯。

03根因：失敗的市場被另一市場的日期「頂替」

lib/data/managers/sync_manager.dart 在組裝 SyncResult 時，若某一市場本次抓取失敗（fetchOTC() 重試 3 次後仍回傳空清單），其日期欄位會直接 fallback 成 latestDate——也就是另一個市場成功抓到的日期：

修正前
return SyncResult(
  ...
  listedDate: listedDate.isNotEmpty ? listedDate : latestDate,
  otcDate:    otcDate.isNotEmpty    ? otcDate    : latestDate,  // ⚠️ 上櫃失敗時，直接冒用上市的日期
);

這造成一條被完全隱藏的失敗鏈路：

① fetchOTC() 失敗 → 回傳 []，otc.isEmpty == true ② saveOtcSnapshot() 被略過 → 本地沒有 otc_今天.json 這個檔案 ③ SyncResult.otcDate → 被覆蓋成 latestDate（冒充「今天」） ④ 上市/上櫃日期不一致警示 → 因為兩個回報日期「看起來一致」，完全不會觸發 ⑤ HistoryRepository 讀取 → 找不到今天的上櫃檔案，靜默 fallback 到最近一份舊快照（例如前一天） ⑥ 個股排行畫面 → 顯示「今天」標籤，內容卻是舊資料（4991 的 24.04 億） ⑦ SQLite 歷史寫入 → 舊資料被誤標成「今天」永久寫入歷史表
為什麼手動刷新也沒用？ forceSync 只是跳過時間護欄、強制重新呼叫 API，如果那次呼叫本身仍然失敗（例如當下的網路狀況、TPEX 端瞬時限流等外部因素），上述遮蔽鏈路依然會發生——使用者完全看不到任何錯誤提示，只會看到「刷新了但數字沒變」。

04修正內容

當任一市場本次抓取失敗時，回報的日期改為該市場「本地實際可用」的最新一筆舊日期，不再冒用另一市場的 latestDate：

修正後
// 若上市/上櫃其中一方本次抓取失敗，回報日期改用本地實際可用的舊日期
String reportedListedDate = effectiveListedDate;
if (listed.isEmpty) {
  final localListedDates = await storageService.listListedDates();
  reportedListedDate = localListedDates.isNotEmpty ? localListedDates.first : '';
}
String reportedOtcDate = effectiveOtcDate;
if (otc.isEmpty) {
  final localOtcDates = await storageService.listOtcDates();
  reportedOtcDate = localOtcDates.isNotEmpty ? localOtcDates.first : '';
}

return SyncResult(
  ...
  listedDate: reportedListedDate,
  otcDate: reportedOtcDate,
);

修正後的效果：

  • 不會再有「宣稱今天、實際是舊資料」的假象。
  • 首頁的上市/上櫃日期不一致警示會正確觸發，明確告訴使用者「上櫃資料可能抓取失敗或延遲」。
  • 不會再把舊資料誤標成今天，寫進 SQLite 歷史表造成永久污染。
檔案：lib/data/managers/sync_manager.dart；flutter analyze 全專案通過。

05已知限制／後續待觀察

這次修正解決的是「失敗被隱藏」的問題，但無法確定當下那次 fetchOTC() 為何會失敗——開發機用 curl 直接測試官方 API 是正常的，實際失敗原因可能是使用者裝置當下的網路狀況、或 TPEX 端瞬時限流等外部因素，無法在這次修正中複現或根除。

後續若再遇到類似狀況，請先確認首頁有沒有跳出橘色的「日期不一致」警示：
  • 有警示 → 代表這次修正生效，問題是網路面的抓取失敗，可以再點一次「立即重新整理」重試。
  • 修正後仍完全沒有警示、卻還是舊資料 → 代表還有其他未發現的問題，需要再深入查。
